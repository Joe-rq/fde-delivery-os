# 阅读与实践路线

原则：每周阅读最多只服务一个实践产出。没有产出的阅读，不计入 FDE 能力证据。

## 第 1 周：定义一个真问题

阅读：OpenAI FDE、FDE Guidance Book 的 PSF/影子工作、本仓库现场发现方法。

产出：

- 一页问题说明；
- AS-IS 流程；
- 五张地图的最小版本；
- 机会评分和 Go / Hold / No-Go。

验收：不了解业务的人能复述流程，且知道下一个要验证的未知是什么。

## 第 2 周：选择最小技术闭环

阅读：Anthropic Building Effective Agents、OpenAI Agent Guide、12-Factor Agents、MCP。

产出：

- 规则 / 检索 / Workflow / Agent 四种备选方案；
- 工具合同与权限表；
- 人工确认点和失败降级；
- 一条端到端可运行链路。

验收：能解释为什么没有选更简单或更复杂的架构。

## 第 3 周：让 Eval 成为合同

阅读：Anthropic Agent Evals、OpenAI Evals、Phoenix 的 dataset/experiment 概念。

产出：

- baseline / target / acceptance / outcome 四层指标；
- 常规、边界、高风险、故障注入样本；
- 代码、模型和人工 grader；
- 错误分类与发布/回滚门槛。

验收：其他人按计划复跑时，能得到同口径结果并定位失败类型。

## 第 4 周：从能跑进入可采用

阅读：NIST AI RMF、OWASP GenAI、OpenAI Harness Engineering、本仓库生产化 Playbook。

产出：

- 威胁模型和最小权限表；
- 日志、追踪、幂等、重试和回滚设计；
- 无陪同用户试运行；
- 一页作品案例，明确已证明/未证明。

验收：作品同时包含可运行系统、可复算证据和诚实边界。

## 循环规则

每完成一个项目，把以下内容回写到本仓库：

1. 新出现的失败样本；
2. 被证伪的假设；
3. 可复用的判断单元；
4. 下次可以减少的定制工作；
5. 真实用户采用或拒绝的证据。
