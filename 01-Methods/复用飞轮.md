# 复用飞轮

## 第一次解决问题，第二次检验模式

```mermaid
flowchart LR
    A["现场摩擦"] --> B["碎石路方案"]
    B --> C["运行与 Eval 证据"]
    C --> D["跨案例比较"]
    D --> E["Skill / 连接器 / 模板 / 产品能力"]
    E --> F["下一次更快交付"]
    F --> A
```

## 三级复用资产

1. 知识复制：清单、访谈脚本、SOW、Runbook、培训材料。
2. 组件复制：连接器、规则单元、评测 harness、部署模板。
3. 产品复制：把重复定制抽象成平台能力或标准方案。

## 每个项目的撤场复盘

- 哪些判断只适用于这个客户？
- 哪些模式在其他项目也出现过？
- 哪些动作第二次不应再手工做？
- 哪些失败样本应进入 Eval？
- 哪些现场摩擦应形成 Field RFC？
- 哪些规则能成为 Skill，哪些必须保持人工判断？

## 三个硬指标

- 复用率：新项目使用已有资产的比例。
- 采用率：系统是否被真实用户稳定使用。
- 反馈率：现场发现进入产品/平台路线图的比例与速度。

如果第二个同类项目仍从零开始，说明第一次只是完成了交付，没有形成 FDE 复利。
