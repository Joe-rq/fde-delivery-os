# 启衡报销预审：FDE 课程沙盒 PoC

> 事实边界：**“启衡”是课程沙盒中的虚构场景；本页只描述 FDE 课程沙盒 PoC / 合成数据。它不是付费客户、生产交付、客户上线、真实采用或业务 ROI 证据。**

## 要验证的问题

在合成的报销流程中，能否把模糊的“让 AI 审单”收敛为一个受控闭环：

`合成单据 → 确定性核对 → 特批判断 → APPROVE / REJECT / FLAG 建议 → 人工终决`

重点不是替人作最终决定，而是练习如何同时处理范围、系统约束、异常、评测和人工责任。

## 沙盒约束

1. 只通过课程提供的沙盒接口读写，不直连数据库。
2. 系统只生成审核建议，正式状态由人工控制。
3. 写操作使用最小权限，并保留可回滚和审计思路。
4. 规则、数据缺失、接口故障和人工升级分别处理。
5. 核心判断建立独立 Eval，不用 Demo 印象代替验收。

## 可公开的交付链摘要

| 阶段 | 公开摘要 | 证据强度 |
|---|---|---|
| Discovery | AS-IS / TO-BE、事实/假设、范围与人机责任 | 沙盒练习记录，原始材料未公开 |
| SOW | 目标、依赖、里程碑、验收与范围外 | 沙盒练习记录，原始材料未公开 |
| 最小链路 | 读取合成单据、生成建议、模拟回写复核字段 | 本地沙盒运行摘要 |
| Judgment | 有特批 / 无特批 / 查询失败三分支 | 本地测试摘要 |
| Eval | 30 条合成样本中 27 条完全一致，即 90% | 不可由本仓库独立复算 |
| 操作入口 | 菜单、报告、帮助和模拟写入 | 本地沙盒运行摘要 |

“完全一致”指最终判定与违规代码同时一致；它不是准确率的生产承诺。

## 三个可迁移判断

### 1. 先定义业务决定，再选 AI 机制

任务被重写为“在人工作最终决定前，哪些核对可稳定标准化”，因此规则、模型与人工的责任可以分别验收。

### 2. 规则命中前检查例外

特批属于独立证据。判断使用三态输出：

- 证据支持有效特批 → `EXEMPTED`；
- 证据支持无特批 → `RULE_APPLIES`；
- 数据缺失、查询失败或时序冲突 → `FLAG`。

### 3. 让 Eval 指向下一项工程工作

30 条合成样本中的 3 条差异集中在票面字段证据缺失。正确结论是“需要补强输入证据和回归样本”，不是“已经完成 90% 的生产目标”。

## 已证明 / 未证明

### 仅在课程沙盒内得到早期证据

- 合成数据可以经过读取、判断、建议和受控写入形成最小闭环。
- 例外判断可以显式区分规则适用、规则豁免和证据不足。
- 30 条合成样本可以用于发现输入证据缺口。

### 本仓库没有证明

- 真实组织、真实接口、真实票据或真实用户中的表现；
- 生产稳定性、权限审查、安全评估、长期运维和 SLO；
- 用户采用、人工节省、业务收益、付费、续约或 ROI；
- 任何跨客户复用效果。

## 公开证据策略

原始课程正文、合成数据集、私有运行日志和本地交付物不复制进公开仓库。公开页面只保留方法摘要、指标口径和限制；如未来获得可公开授权，应先完成来源、隐私和许可复核，再补充可复算的最小证据包。
