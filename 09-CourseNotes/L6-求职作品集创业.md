# 第六课 · FDE 求职/作品集/创业路径

> **来源**：FDE 共学营第一期。本页只记录受课程启发的方法论骨架与项目映射，**不复制课程正文、PPT 或讲义**。课程原始内容受版权保护，公开改编许可未确认，详见 [来源登记](../06-Sources/来源登记.md)。
>
> **覆盖**：仅大纲（无 PPT，未读正文）

> **案例口径**：本文提及的「启衡」指启衡 FDE 课程沙盒 PoC（合成数据），非真实客户或生产证据；详见 [来源登记](../06-Sources/来源登记.md)。

## 核心论点

把同一套交付判断（Discovery→定界→Eval→采用→复用）同时转化为招聘方可识别的证据与客户可付费的闭环——简历/作品集与 Solo 商业闭环共用一条证据链，单干依赖独立节点互联而非孤军。

*本课基于课程文档大纲标题推断，未读 PPT 正文，要点为标题级推断。*

## 方法论地图

### 求职方向选择与岗位识别（标题 1-3）

- **要点**：
  - 项目交付完成后有两条路，需显式判断而非随缘
  - FDE 非单一工种，团队内有 Discovery 型 / 构建型 / 采用型等分工
  - 市场存在挂名 FDE 的伪岗位，用交付闭环完整度反向识别
- **框架/术语**：项目完成后两条路，FDE 角色分工，识别真正 FDE 岗位
- **项目对应**：[个人FDE定位](../00-Map/个人FDE定位.md)、[FDE能力地图与成长路线](../00-Map/FDE能力地图与成长路线.md)、[FDE资源矩阵](../08-Resources/FDE资源矩阵.md)（OpenAI FDE 岗位页作真岗位样本）
- **Gap**：⚠️缺口——有个人定位与能力地图，但缺①职业路径分叉框架②团队内角色分工模型③真假岗位反向识别清单。能力八维是「要证明什么」，不是「团队里谁做什么」。
- **吸收建议**：在 00-Map 新增「FDE 职业路径与岗位识别」页，把公开证据表反转为岗位识别清单（JD 是否含 Discovery / 现场 / 采用回流 / 复用），用 OpenAI 岗位页做基准。

### 简历四个信号与作品集质量（标题 4-5）

- **要点**：
  - 简历应体现四个可识别信号（推断对应发现/定界/Eval/采用四类证据）
  - 作品集价值在交付判断与证据链，而非 GitHub repo 或 star 数
  - 完整页面制造的交付错觉反而是负信号
- **框架/术语**：FDE 简历四个信号，作品集不是 GitHub 数量
- **项目对应**：[作品集路线](../07-Portfolio/作品集路线.md)（8 项证据结构）、[公开发布说明](../07-Portfolio/公开发布说明.md)（一页简历）、[启衡课程沙盒作品页](../07-Portfolio/启衡课程沙盒作品页.md)（30 秒介绍+诚实边界）
- **Gap**：🔧补强——质量信号已被项目大量覆盖，但「简历四信号」未抽象为显式可勾选框架，一页简历表述仍是描述性段落而非信号清单。
- **吸收建议**：把 8 项证据结构压缩为「简历四信号」对照表（信号→作品证据→证据强度）。四信号名称待正文确认，先用发现/定界/Eval/采用占位。

### 面试考判断（标题 6）

- **要点**：
  - 面试核心考判断，而非知识记忆或 LeetCode
  - 典型场景：模糊定界、规则命中≠业务结论、失败样本处理、人机边界取舍
- **框架/术语**：FDE 面试考判断
- **项目对应**：无直接资产；间接相关 [个人FDE定位](../00-Map/个人FDE定位.md)、[启衡报销预审PoC](../04-Cases/启衡课程沙盒报销预审PoC.md)（规则命中≠业务结论反例）、01-Methods 取舍记录
- **Gap**：⚠️缺口——项目零覆盖面试准备：无判断题库、无典型反例集、无评分自检表，却是求职核心交付物。
- **吸收建议**：新增 07-Portfolio/面试判断准备.md，从十步闭环每步抽 1-2 道判断题与失败反例，配评分 rubric，复用现有案例作答题样本。

### Solo FDE 商业闭环（标题 7-8）

- **要点**：
  - Solo FDE 需三段式商业闭环（推断为获客→交付→资产化/复用）
  - E-A-D 是课程缩写，主张单干不等于独自完成
  - 独立交付仍依赖协作网络，Solo 的是商业主体而非执行孤岛
- **框架/术语**：Solo FDE 三段式商业闭环，E-A-D（单干≠独自完成）
- **项目对应**：[复用飞轮](../01-Methods/复用飞轮.md)（资产化思想，作第三段基础）、[FDE交付闭环](../00-Map/FDE交付闭环.md)（证据链→变现阶梯）
- **Gap**：⚠️缺口（本课最大）——项目纯交付方法论，无商业模式/定价/获客/Solo 运营。复用飞轮只覆盖资产化一段，缺获客与变现；E-A-D 无对应。
- **吸收建议**：正文确认后新增 02-Playbooks/Solo-FDE商业闭环.md，以复用飞轮为第三段，向上补获客（机会评分卡做线索筛选）与变现（SOW 做定价边界）。

### 独立节点交付网络（标题 9）

- **要点**：
  - 独立 FDE 之间形成节点协作网络，承接超单人能力的交付
  - DeltaEcho 是课程对此网络的命名（定义待正文确认）
- **框架/术语**：DeltaEcho 独立节点交付网络
- **项目对应**：无直接资产；间接相关 skills/ 多 Skill 协作、05-Engineering 生产 Agent 参考架构、[项目复盘与产品化](../02-Playbooks/项目复盘与产品化.md)（节点间资产流转雏形）
- **Gap**：⚠️缺口——无 FDE 间协作网络/组织形态/节点互联协议；DeltaEcho 术语无对应，属组织创新概念，与项目「单人方法论」层级不同。
- **吸收建议**：先在 [来源登记](../06-Sources/来源登记.md) 登记 DeltaEcho 与 E-A-D 出处（C 级受限启发），正文确认前不写成既定方法。

## 本课最值得吸收的点

1. **Solo 商业闭环是最大缺口**：复用飞轮只覆盖资产化一段，需向上补获客（机会评分卡）与变现（SOW 定价），把交付方法论升级为可独立运营的 Playbook。
2. **面试判断题库零覆盖**：求职场景核心交付物却完全没有——从十步闭环每步抽典型判断题与失败反例（如「规则命中≠业务结论」），配评分 rubric。
3. **简历四信号显式化**：有 8 项证据结构素材但未压缩为可勾选信号清单，一页简历仍是描述而非信号——压缩为四信号对照表。
4. **岗位反向识别清单**：个人定位证据表是「我有什么」视角，缺「岗位是不是真 FDE」的反向视角——反转为岗位识别清单，用交付闭环完整度过滤伪岗位。
5. **E-A-D / DeltaEcho 先登记后确认**：两个组织形态概念项目无对应——先在来源登记标 C 级受限启发，正文确认前不写成既定方法，避免编造课程内容。
