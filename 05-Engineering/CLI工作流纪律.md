# CLI 工作流纪律

[Production Agent 参考架构](Production-Agent参考架构.md) 讲运行时架构；这一篇讲人怎么用 CLI Agent 把活干好——FDE 的日常工程纪律。

## 为什么是 CLI 不是网页 AI

网页 AI 在企业场景撞四道墙：不能读写整个代码库、不能执行系统命令、不能访问内网 API/数据库/遗留系统、不能被脚本编排。这四项恰是企业刚需。CLI Agent 能直接进客户内网生产环境，对接代码库、系统命令、内网资源、CI。

## 三类工具分工

| 工具 | 适合 |
|---|---|
| Claude Code | 复杂多步、长上下文、固化工作流 |
| Codex CLI | 脚本化、CI、沙箱隔离、批量任务 |
| Cursor | 重度改码、需肉眼盯 diff |

## 通用起手式（三家一致）

1. 先写上下文文件（AGENTS.md / CLAUDE.md）。
2. 需求走 SOW 到 SPEC，不直接下指令。
3. 小步下指令，一次一个最小增量。
4. 每步让 Agent 自证（截图或跑测试）。

铁律：永不从聊天记录直接改代码。

## CLI 五类日常动作

- 读懂存量：陌生代码库几分钟出架构摘要。
- 接内部系统：OpenAPI / curl 转类型化客户端 + mock 层。
- 动系统：起服务、迁移、装依赖、跑测试、部署。
- 无人值守：接入 CI 与定时任务。
- 多模态摄取：客户系统截图直接喂。

## 人机协作规模

| 模式 | 上限 | 瓶颈 |
|---|---|---|
| 盯屏并行 | 3–5（上限约 10） | 个人 review 带宽 |
| 异步派活 | 10–60 | 任务定义质量 |
| 单任务 fan-out | 数百 | 脚手架 |

净产出瓶颈在 review 不在生成：重度用户原始产能约 4 倍，但年交付净增益仅约 12%。扩 agent 数 ≠ 提净产出；决定差异的是脚手架（plan / rubric / hooks / WIP 控制），不是换模型。

## 四条纪律

上下文先行 → 需求文档化 → 增量自检 → 全程留痕。留痕是双用途资产：调试可回放，交付即文档。
