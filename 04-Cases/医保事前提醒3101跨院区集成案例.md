# 医保事前提醒 3101 跨院区集成:适配差异、根因定位与违规检出

> 事实边界:本案例来自作者在真实医疗信息化交付中负责的医保 3101 事前提醒接口跨院区适配工作,已脱敏--院区名统一替换为某康养社区 A–F;厂商名、类名、全局变量名泛化(医保端口类/医保对照类/医保审核类);患者 ID、参保人 ID、追溯码不出现;源码与原始调试报告不进公开库。技术栈如实描述(InterSystems IRIS for Health + 厂商医院信息系统),行内可推断但不点名。证据强度:接口在生产/测试环境真实运行并检出违规;调试细节为作者实测。不可由本仓库独立复算;所有数字仅支持其所述样本与口径。

## 要验证的问题

医保 3101 事前提醒接口要求医院在开具医嘱/收费时,把费用明细上传医保端,由医保两库(药品/诊疗)规则返回违规提示。难点:同一厂商医院信息系统 部署在多个院区,各院区版本、方法签名、参数取值不一,接口字段(如收费项目等级 hilistLv、收费类别 ChrgType)在不同院区/不同代码路径下取值不一致,直接导致违规漏报或报销金额错误。可证伪的问题:**能否在不改医保接口契约的前提下,定位跨院区适配差异与字段取值根因,让违规检出在所有院区一致生效?**

## 现场发现:跨院区适配差异

至少 5 个院区(A–E)部署同一厂商医院信息系统 的不同版本。以"获取项目医保信息"方法为例,跨院区代码对比发现两类签名:

| 维度 | A 院区版 | B 院区版 |
|---|---|---|
| 入参 | 执行记录 ID 单参数 | 医嘱 ID 或执行记录 ID + 院区 ID,三参数 |
| 院区处理 | 自动获取 | 支持手动传入 |
| 账单获取 | 固定执行记录索引 | 按参数类型动态选索引 |
| 聚合 | 按收费项简单累加 | 按收费项 + 单价双重聚合 |
| 未生成账单 | 不支持 | 支持新接口兜底 |

签名差异意味着同一业务问题在不同院区要走不同调用路径,排查必须逐院区对比源码,不能假设一致。[Private-evidence · 核验于 2026-05~06]

## 根因定位:两个关键空值

### HiListCode / HiListName 为空

执行某记录时,返回的医保目录码与名称为空。逐段调试医保对照类的 30 段返回串,定位可能原因:医保对照表(全局节点)下无该收费项记录;或医保类型参数取值不匹配;或对照类返回段位与字段定义错位。排查靠在终端逐段 write 返回串 + 反查对照表索引,而非读代码猜。

### hilistLv 空值导致报销金额错误

hilistLv(收费项目等级,甲/乙/丙类)决定报销比例。逻辑分析发现状态机矛盾:

- 医保端口类对非西药项目无 hilistLv 处理逻辑,直接透传,可能为空;
- 空值流转到医保审核类时,被强制设为"03"(丙类,报销最少);
- 格式还不一致:数据库存"1"与"01"走不同转换路径。

> 这是"改 A 坏 B"的典型:为防空值崩溃加默认值,默认值却选了最不利于患者的丙类。若不靠端到端调试,只看任一节点都发现不了。属规则/流程类失败。

## 业务结果:真实违规检出

某院区(F)3101 接口在生产运行中真实检出违规:艾地骨化醇软胶囊(0.75ug*14粒/盒),违规金额 51.24 元(medfee_sumamt)。这条记录证明接口在真实医保两库规则下生效,违规检出链路打通。[Private-evidence · 单条违规样本 · 不可由本仓库独立复算]

## 失败复盘

- **调试残留风险**:排查时写入临时调试全局变量,必须显式清理(kill),否则残留进生产。本案例调试流程含清理步骤,但作为流程红线记录:调试代码不得隐式依赖调用上下文、不得留临时全局。
- **空值默认值陷阱**:见上,hilistLv 空值默认丙类是"防崩溃却伤患者"的设计,需在对照类统一处理 + 移除审核类的强制丙类逻辑。
- **格式不一致**:同一字段两种格式两种路径,需统一为两位格式。

## 已证明 / 未证明

**已证明(在作者交付环境)**:5+ 院区适配差异真实;两个空值根因靠逐段调试定位;某院区真实违规检出 51.24 元证明接口生产运行。

**本仓库没有证明**:全院区违规检出一致性(部分院区仍在验证);报销金额错误的实际影响范围;长期 SLO。空值默认丙类是已识别风险,修复状态随各院区排期。
