## 每个作品的统一证据结构

1. 问题与主张状态；
2. AS-IS 与证据来源；
3. 约束、范围和取舍；
4. 架构与人机边界；
5. Eval、失败样本和运行结果；
6. 采用与业务指标；
7. 关键判断；
8. 复用资产与未证明项。

没有证据的部分留空或标记未证明，不用完整页面制造完整交付的错觉。

## 三种颗粒度

同一案例输出三种载体：

| 颗粒度 | 用途 | 内容侧重 |
|---|---|---|
| 社媒长文 | 公开传播 | 完整复盘（含失败） |
| GitHub README | 技术背书 | 业务背景 + Eval 结果，少贴代码 |
| 一页纸 PDF | 面试前发 | 浓缩亮点 |

## 脱敏红线

公开案例必须脱敏三件套：

- 客户名抽象成行业描述；
- 数据换结构相同的模拟数据；
- 截图打码（尤其金额、人名）。

除非合同有免责条款，否则一律脱敏。没有企业客户时的冷启动阶梯：把客户逐级换小（大企业→小微企业→个体户→亲友→自己），真实使用 + 反馈迭代 > 只为展示的 Demo。
