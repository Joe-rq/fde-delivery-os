# 公开 FDE 定位

## 一句话定位

> 在业务现场与 AI 工程之间做翻译：把模糊工作流变成可定界、可评测、可运行的系统，再把交付判断沉淀为 Skills、模板和工程约束。

公开身份只使用 GitHub 账号 [Joe-rq](https://github.com/Joe-rq)，仓库不收录真实姓名、客户身份或雇主内部信息。

## 当前公开证据

| 能力 | 公开证据 | 边界 |
|---|---|---|
| 机会重构 | 机会评分、事实/假设分层、Go / Hold / No-Go | 方法资产，不等于商业结果 |
| 业务发现 | 五张地图、影子工作问题、最小闭环 | 需在授权项目中验证 |
| 范围与验收 | SOW、Eval、人工边界和发布门模板 | 模板数量不是采用证据 |
| 判断资产化 | 3 个可调用 Skills、每个 3 条 eval 场景 | 尚无跨运行时评分报告 |
| 工程实践 | 关联公开工程仓库 | 具体能力以各仓库证据为准 |
| 证据治理 | 合成沙盒、项目候选、公开事实和限制分层 | 私有证据不进入公开库 |

## 必须保持诚实的两条边界

- 启衡只表示 **FDE 课程沙盒 PoC / 合成数据**；没有真实客户、付费、生产采用或 ROI 证据。
- HIS 问题诊断是 `project-candidate / discovery-needed`；没有已落地或正在交付的事实。
