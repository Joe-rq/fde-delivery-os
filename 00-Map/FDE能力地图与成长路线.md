# FDE 能力地图与证据路线

## 八维能力

| 维度 | 需要证明的不是“学过”，而是 |
|---|---|
| 基础工程 | 能写、测、调试并维护端到端系统 |
| AI 应用工程 | 能在规则、RAG、Workflow、Agent 和人工之间取舍 |
| 企业集成 | 能处理 API、权限、身份、旧系统和数据质量 |
| Eval 与可观测 | 能定义好坏、跑回归、解释失败与漂移 |
| Discovery | 能从模糊表达进入实际流程和业务结果 |
| 干系人协同 | 能对齐使用者、业务、IT、安全和决策人 |
| 产品判断 | 能区分一次性需求与可复用模式 |
| 端到端交付 | 能在不完整信息下推进到采用与复用 |

## 三阶段公开证据路线

### 阶段 1：把沙盒练习变成诚实作品

- 公开 **FDE 课程沙盒 PoC / 合成数据** 的方法、口径和限制；
- 不公开课程正文、原始交付证据或本地材料；
- 让读者能区分方法证据、工程证据和业务效果证据。

### 阶段 2：验证项目候选

- 将 HIS 问题诊断严格保持为 `project-candidate / discovery-needed`；
- 只有获得合规授权、脱敏样本和责任人后，才建立 baseline 与 Eval；
- 在 Agent 之前比较表单、SOP、规则和搜索方案。

### 阶段 3：补齐生产与采用证据

- 展示可恢复运行、人工接管、权限审计和回归门；
- 用授权证据记录采用、改判、失败类型和任务耗时；
- 至少比较两个合规项目后，再主张跨场景复用。

## 作品合格线

每个作品至少覆盖：

`问题 → 证据状态 → 约束 → Scope → 架构 → Eval → 运行证据 → 采用 → 复盘 → 复用`

缺少的环节必须明确标注“未证明”。页面完成度、资产数量和 Demo 可运行都不能替代业务效果。
