# 项目复盘与产品化

## 复盘顺序

1. 结果：业务、质量、采用和运行指标达到什么。
2. 偏差：哪些目标、范围、排期或假设发生变化。
3. 决策：哪些判断正确，哪些判断代价最大。
4. 失败：按数据、规则、模型、工具、权限、流程、组织分类。
5. 复用：哪些资产能让第二次更快。
6. 产品回流：哪些不是客户特例，而是平台缺口。

> 失败分类实例（私有证据）：血库接口 XML 转义失败归为"规则/工具"类--根因是 ObjectScript `$tr` 做字符级映射而非子串替换（`$tr("<0.05","<","&lt;")` 会把 `<` 映射到 `&lt;` 的首字符 `&`，结果变成 `&0.05`）；转义顺序须 `&` 先于 `<`，否则把生成的 `&lt;` 再次转义成 `&amp;lt;`；全角 `＜` 须用 `$c(65308)` 表示避免编码问题；Caché 缩进必须纯 Tab。修复改用 `$replace`。[Private-evidence · 核验于 2026-05~06 · 不可由本仓库独立复算]

## 四类沉淀

| 类型 | 典型产物 |
|---|---|
| Know-how | 访谈问题、清单、Runbook、案例 |
| Judgment | 规则单元、rubric、Skill、人工升级条件 |
| Engineering | 连接器、评测脚本、部署模板、监控 |
| Product | Field RFC、产品需求、模型改进样本 |

> Know-how 沉淀实例（私有证据）：经验索引 INDEX（日期 / 经验文件 / 关键词 / 业务域 / 院区）+ 五段经验卡（问题描述 / 根因分析 / 解决方案 / 关键经验 / 关联），归档时自动追加一行、晨检时自动检索，把"踩过的坑"变成"下次能查到的资产"，不靠人记得去翻。完整范式见 [医疗交付团队知识库治理](../04-Cases/医疗交付团队知识库治理-从L2到L3跃迁.md)。[Private-evidence]

## 泛化检验

对每个拟复用资产回答：

- 它来自几个不同流程或客户？
- 哪些变量必须配置，哪些逻辑真正通用？
- 若脱离原客户数据和术语，是否仍成立？
- 有什么测试证明它没有过拟合一个样本？
- 谁维护，何时失效，如何回滚？

## 撤场交接

- 业务 owner、系统 owner、支持 owner 明确；
- 操作、异常、恢复和升级路径写入 Runbook；
- 已知限制公开；
- Eval 与版本记录可重复；
- 30/60/90 天复盘已预约或自动化。
