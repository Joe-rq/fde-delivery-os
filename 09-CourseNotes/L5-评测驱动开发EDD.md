# 第五课 · 让评测成为 Agent 迭代主控回路（EDD）

> **来源**：FDE 共学营第一期。本页只记录受课程启发的方法论骨架与项目映射，**不复制课程正文、PPT 或讲义**。课程原始内容受版权保护，公开改编许可未确认，详见 [来源登记](../06-Sources/来源登记.md)。
>
> **覆盖**：PPT 23 页

> **案例口径**：本文提及的「启衡」指启衡 FDE 课程沙盒 PoC（合成数据），非真实客户或生产证据；详见 [来源登记](../06-Sources/来源登记.md)。

## 核心论点

Agent 的评测不能停在交付末端的验收动作，而要升级为驱动整个迭代的主控回路——用可测量基线、失败分类、持续回流刷新的测试集，替代「感觉变好了」的主观判断。

## 方法论地图

### 四幕故事与 Agent 特有的四类 Bug

- **要点**：
  - 传统工程每步都做对，系统仍可能整体失败——错的不是人或专业度，是这套循环本身在 AI 应用上失效
  - 四幕对应四类本质不同的 bug：需求从未显式定义、静默失败、局部全对整体失败、修东墙塌西墙的回归
  - 失败可见性取决于评估者的领域知识：领域盲区即评估盲区
  - Dijkstra 定理：测试只证伪不证真，AI 系统无法靠穷举保证正确，只能靠持续测量
- **框架/术语**：静默失败、局部全对整体失败、回归塌陷、需求未定义型 bug、Dijkstra「测试只证伪不证真」
- **项目对应**：[04-Cases/启衡课程沙盒报销预审PoC.md](../04-Cases/启衡课程沙盒报销预审PoC.md)（违规样本差异定位）；[01-Methods/Eval与验收.md](../01-Methods/Eval与验收.md)（错误分类 + Agent 三类高隐蔽失败）
- **Gap**：✅已覆盖——Agent 三类高隐蔽失败已落实于 [Eval与验收.md](../01-Methods/Eval与验收.md)，配最小检测手段
- **吸收建议**：无需补充

### EDD 根因与主控回路定位

- **要点**：
  - 五大根因→五条推论：不透明→经验测量；随机性→多次统计；局部≠全局→以系统为测量单位；隐性知识→人对样本逐条判→抽 rubric→训裁判；分布漂移→持续回流 + 刷新率
  - EDD 把评估从末端 QA 前移并升级为驱动迭代的主控回路
  - 核心类比：外挂训练——数据↔生产失败、loss↔评估指标与发布门、泛化↔长尾表现、参数更新↔改 prompt/RAG/工具/流程
  - 四陷阱：过拟合、测试集污染、数据飞轮、生成便宜验证贵
- **框架/术语**：EDD（Evaluation-Driven Development）、主控回路、外挂训练类比、五大根因→五推论、四陷阱
- **项目对应**：[00-Map/FDE交付闭环.md](../00-Map/FDE交付闭环.md)（Eval 是十步闭环第 7 步）；[01-Methods/Eval与验收.md](../01-Methods/Eval与验收.md)（主控回路 + 外挂训练四陷阱表）
- **Gap**：✅已覆盖——主控回路定位与外挂训练四陷阱已落实于 [Eval与验收.md](../01-Methods/Eval与验收.md)，每个陷阱配一条项目纪律
- **吸收建议**：无需补充

### 文档治理与最小产品契约

- **要点**：
  - 事实/决定/修复三类记录不可省：AI 开发中上下文会被压缩、切窗口、换 runtime
  - 严格文档治理让上下文可扩展、行为可追溯，是「涌现」的前提
  - 写代码或评测前，先锁定最小产品契约五要素：服务对象与任务、完成判据、红线、可用数据与工具、必须人批准的动作
  - 契约既是产品边界，也是评测判分依据
- **框架/术语**：工作纪律 101、三类必备文档（事实/决定/修复）、最小产品契约五要素、P90/P95 自动化门槛
- **项目对应**：[03-Templates/需求说明清单.md](../03-Templates/需求说明清单.md)（问题陈述/角色/范围内外/人机责任/Baseline）；[03-Templates/SOW模板.md](../03-Templates/SOW模板.md)（目标用户/AI 可做与人做/回滚停止条件）；[03-Templates/项目复盘模板.md](../03-Templates/) + decisions 示例
- **Gap**：🔧补强——契约五要素分散在需求清单和 SOW 两个文件，缺「动手前先锁定的最小契约」这种紧凑单元；文档治理作为涌现前提的视角未显式表述
- **吸收建议**：在 [03-Templates/](../03-Templates/) 新增「最小产品契约」轻量模板（5 字段），作为需求清单与 SOW 的前置浓缩版，写代码或评测前必须先填

### 评测对象 = 执行轨迹 与测试集构建

- **要点**：
  - Agent 评测单元应是完整执行轨迹（trace），不是最终回复；答案对≠系统对
  - 错误会沿轨迹传播并被随机性放大
  - 测试集按回答策略 ABCD 分层：直接可答 / 需先澄清 / 只能部分答 / 该拒答或转人工——评的是「处理路径选对没」
  - 五维度：代表性、覆盖性、诊断性、保密性（过拟合检测）、新鲜度（刷新率）；后两项最易忽视
  - 五来源：生产随机、生产失败、专家刁钻、合成变异对照、盲注入（big-dog 藏样验真本事）
- **框架/术语**：trace 评测单元、ABCD 回答策略分层、测试集五维度、测试集五来源、盲注入
- **项目对应**：[05-Engineering/Production-Agent参考架构.md](../05-Engineering/Production-Agent参考架构.md)（七层含 Trace 层）；[03-Templates/Eval计划模板.md](../03-Templates/Eval计划模板.md)（开发/回归/隐藏集分组）；[skills/fde-eval-acceptance/SKILL.md](../skills/fde-eval-acceptance/SKILL.md)（常规/边界/高风险/故障注入）
- **Gap**：⚠️缺口——trace 未作为独立评测单元（模板仍以任务结果为单元）；缺 ABCD 路径分层；保密性/新鲜度未命名；缺合成变异与盲注入两个主动构造渠道
- **吸收建议**：fde-eval-acceptance 第 4 步增加 ABCD 分层（与风险分组正交）；Eval 计划模板增加「来源渠道」「保密性/新鲜度」列；05-Engineering 明确 trace 为一级评测单元

### 结果判断七类型与测试集迭代治理

- **要点**：
  - 一次失败≠系统失败，结果至少分七类型分别处置：有效通过、有效系统失败、概率性失败、评估器失败、测试环境失败、规格缺口、权衡结果
  - 关键纪律：概率性失败多次重跑测失败率；评估器失败修评估器并使历史结论失效重跑；权衡结果看硬约束和价值函数、不看单一总分
  - 测试集是活资产，六种迭代动作：新增、升级加严、改变职责降为只观测、调整权重不改案例、重新标注、退役
  - 退役不等于删除：保留历史便于回溯，防重蹈覆辙
- **框架/术语**：结果七类型、概率性失败（多次重跑测失败率）、评估器失败（失效重跑）、权衡结果（看价值函数）、测试集迭代六动作、退役不删
- **项目对应**：[01-Methods/Eval与验收.md](../01-Methods/Eval与验收.md)（错误分类 8 类 + 测试集活资产六动作）；[skills/fde-eval-acceptance/SKILL.md](../skills/fde-eval-acceptance/SKILL.md)（评测口径错误 + 发布门）
- **Gap**：🔧补强——六动作已落实；但「结果七类型→处置动作」这层项目缺：概率性失败多次重跑、评估器失败失效重跑、权衡结果看价值函数三条处置纪律未显式表述
- **吸收建议**：在 [Eval与验收.md](../01-Methods/Eval与验收.md) 增加「结果类型与处置」一节，在按归属的错误分类之外补一层按结果类型的分类

### 有限的安全与职业发展

- **要点**：
  - 安全无通用答案，风险取决于 Agent 实际能力（能调什么工具、能改什么数据）
  - eval 是探针不是护栏：真正限制损失的是系统架构（权限边界、回滚、人在回路）
  - 职业重心从「练技能」转向「建立独占的观察通道」——持续看到别人和模型看不到的现实
  - 警惕 AI 放大默会知识优势时，反向蒸馏走你的默会判断
- **框架/术语**：eval 是探针不是护栏、能力依赖的安全观、独占观察通道、抽象塔
- **项目对应**：[05-Engineering/Production-Agent参考架构.md](../05-Engineering/Production-Agent参考架构.md)（Guardrails/Approval/Rollback + 可靠性原则）；[01-Methods/Eval与验收.md](../01-Methods/Eval与验收.md)（企业 AI 技术红线四条）；[00-Map/个人FDE定位.md](../00-Map/个人FDE定位.md)（八维能力 + 三阶段证据路线）
- **Gap**：✅已覆盖（安全部分扎实覆盖）；🔧补强（职业视角——「独占观察通道」未表述，属可吸收的世界观，非方法骨架 gap）
- **吸收建议**：安全无需改动；在 [个人FDE定位.md](../00-Map/个人FDE定位.md) 补一两句：FDE 的不可替代性在于独占观察通道，并主动防止默会判断被 AI 反向蒸馏

## 本课最值得吸收的点

1. 把 Eval 从十步闭环第 7 步的阶段性产出，重新定位为贯穿迭代的主控回路，用外挂训练类比说清四陷阱（已在 [Eval与验收.md](../01-Methods/Eval与验收.md) 落实）
2. 增加「结果类型决定处置」这层分类：概率性失败多次重跑测失败率、评估器失败失效重跑、权衡结果看价值函数不看单一总分（项目缺）
3. 测试集作为活资产显式化六种迭代动作（已落实），重点守住「退役不删保留回溯」防重蹈覆辙
4. 把完整执行轨迹（trace）确立为 Agent 一级评测单元，与最终答案分开评；并命名 Agent 三类高隐蔽失败（已落实）
5. 补齐测试集两个主动构造渠道（合成变异对照、盲注入 big-dog），把保密性与新鲜度作为测试集质量的显式维度（项目缺）
