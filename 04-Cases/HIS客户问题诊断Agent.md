# HIS 客户问题诊断 Agent

> 当前状态：`project-candidate / discovery-needed`。这是基于通用医疗软件交付模式形成的项目假设，不代表已有客户、客户授权、真实工单、开发、上线、采用或业务效果。

## 候选问题

医疗软件问题上报常可能缺少版本、模块、复现步骤、日志和环境信息，导致支持与研发之间多轮补问。这个现象目前只是待验证假设；在没有合规 Discovery 之前，不能据此设计或声称已交付 Agent。

## 候选最小闭环

```mermaid

    A["问题描述"] --> B["结构化追问"]
    B --> C["检查可授权采集的信息"]

    D --> E["生成分诊建议与证据引用"]
    E --> F["人工确认"]
    F --> G["形成研发升级材料包"]
```

这张图是验证对象，不是已运行流程。

## Discovery 前必须补齐的证据

- 哪类问题高频、耗时或重复补问最多；
- 合格升级材料包需要哪些字段；
- 哪些日志、配置、截图和版本信息可合规采集；
- 哪些步骤适合表单、SOP 或规则，哪些步骤才需要模型；
- 谁负责建议复核、最终处置、权限和审计；
- 哪些数据不得出域或进入公共模型；
- 当前 baseline、样本来源和可接受错误是什么。

## 候选 Eval

以下指标只有在获得授权样本和明确口径后才能建立：

- 信息字段完整率；
- 首轮补齐率；
- 转研发后的再次追问率；
- 分诊一致率与高风险误导率；
- 证据引用可追溯率；
- 人工改判率和越权建议数。

## 明确范围外

- 不自动修改生产数据库或医院核心系统；
- 不在无人复核时输出高风险处置；
- 不把患者、医院或账号敏感数据发送给未批准的模型；
- 不把相似案例检索表述为根因已经定位；
- 不在完成 Discovery 前承诺准确率、节省时间或上线日期。

## Go / Hold / No-Go

当前结论是 **Hold**。下一步不是实现，而是获得合规的影子工作授权，收集少量脱敏样本，并比较表单/SOP、规则检验、搜索与 Agent 的增量价值。满足数据、责任、评测和安全条件后，才进入 SOW。
