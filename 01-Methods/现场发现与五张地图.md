# 现场发现与五张地图

## 影子工作优先于抽象访谈

跟着真实使用者完成一次任务，重点看：

- 打开哪些系统和表格；
- 在哪里复制粘贴、二次核对或绕过官方流程；
- 哪个数据源嘴上不权威、实际上最被信任；
- 发生例外时找谁、为什么找他；
- 哪一步等待、返工、争议或失败最多。

“应该怎样做”来自制度；“实际怎样做”来自行为。两者的差异就是现场机会和风险。

## 五张地图

| 地图 | 要回答 |
|---|---|
| 流程地图 | 触发、角色、输入、动作、判断、例外、输出、指标是什么 |
| 数据地图 | 数据在哪里、谁维护、质量如何、哪一份权威、能否出域 |
| 系统地图 | 哪些系统读写、接口、权限、身份、限流和 legacy 约束 |
| 组织地图 | 发起、使用、配合、验收、预算、运维分别是谁 |
| 政治地图 | 谁受益、谁受损、谁能阻塞、谁是非正式影响者 |

## 一次只问一件事

好的问题短、具体、带证据：

- “这张单你下一步会看哪里？”
- “上一次例外是什么？”
- “这个数字你为什么不信系统？”
- “如果结果错了，谁承担后果？”
- “你最终依据什么决定通过？”

先从数据发现异常，再拿具体单据去问，比空手问“你有什么需求”更有效。

## 现场发现的完成标准

一个不了解该业务的人，能仅凭材料：

1. 复述当前流程；
2. 指出主要摩擦、例外和责任边界；
3. 区分事实、假设与方案；
4. 说出下一步要向谁确认什么。

做不到，说明还没有完成 Discovery。
