# 第四课 · 从CLI入口到企业级Agent生产系统

> **来源**：FDE 共学营第一期。本页只记录受课程启发的方法论骨架与项目映射，**不复制课程正文、PPT 或讲义**。课程原始内容受版权保护，公开改编许可未确认，详见 [来源登记](../06-Sources/来源登记.md)。
>
> **覆盖**：PPT 30 页

## 核心论点

企业 AI 的价值不在一次跑通 Demo，而在把"跨系统、带判断、有责任边界"的关键任务，经选准—说清—装配—稳定运行—验证—沉淀六步生产化，收口为可复制、可治理、可产生能力复利的 Agent 任务资产。

## 方法论地图

### 企业级 Agent 的价值标准与双层平台（页 1-4）

- **要点**：
  - 评判从"能不能跑一次"转向"能不能反复按要求完成"
  - 产品分两层：方案层定"做什么"，基础设施层定"怎么稳定运行、怎么治理复用"
  - 基础设施五项硬指标：准确率 / 可控性 / 安全 / 可观测性 / 高效协同
  - 终极目的是资产沉淀，否则项目退化成一次性外包
- **框架/术语**：Solution + Infra 双层平台、稳定交付四维度（效率/成本/体验/风险）、五大能力硬指标、准确率八层面、五维可控、四步产品闭环
- **项目对应**：[00-Map/FDE交付闭环.md](../00-Map/FDE交付闭环.md)、[05-Engineering/Production-Agent参考架构.md](../05-Engineering/Production-Agent参考架构.md)、[00-Map/FDE能力地图与成长路线.md](../00-Map/FDE能力地图与成长路线.md)
- **Gap**：🔧补强——大方向已覆盖，十步闭环比四步更细；缺三块：Solution/Infra 产品命名、准确率八层面诊断清单、五硬指标未收口成命名框架
- **吸收建议**：在 Production-Agent 参考架构新增"企业级五项硬指标与诊断维度"节，把八层面、五维可控落成可勾选清单；README"与工程案例的关系"段补一句：方法体系层即 Solution、工程案例层即 Infra

### Agent 生产化六步链路与任务分类法（页 5-7）

- **要点**：
  - 六步：选准 / 说清 / 装配 / 稳定运行 / 业务价值 / 沉淀复用
  - 选准是第一步而非搭建，用模板和场景库引导，不从空白画布盲目开发
  - 七类任务分类法，作业务与 IT 共评"该不该优先、模板成熟度如何"的框架
- **框架/术语**：6 步任务链路、7 大任务类型分类法（流程执行 / 审核校验 / 专业问答 / 根因分析 / 决策辅助 / 内容生成 / 运营优化）、任务模板库与场景库
- **项目对应**：[00-Map/FDE交付闭环.md](../00-Map/FDE交付闭环.md)（十步闭环是六步超集）、[01-Methods/项目机会筛选.md](../01-Methods/项目机会筛选.md)
- **Gap**：⚠️缺口——六步链路已覆盖；七类任务分类法完全缺失。项目用十维评分判"值不值得做"，缺第二维度"按类型分类判该怎么生产化、典型路径与风险是什么"
- **吸收建议**：[01-Methods](../01-Methods/) 新增"任务类型与生产化路径"文件，七类各标：典型路径、主要风险、Eval 重点、是否适合首场景；并作为 fde-opportunity-diagnosis Skill 在 Go/Hold/No-Go 之外输出的第二判断维度

### 说清任务与装配能力（页 8-13）

- **要点**：
  - 把"想做 AI"翻译成业务与 IT 共承的可执行结构
  - 三段式：项目 → 业务上下文 → 业务描述；知识按结构拆细颗粒，不当附件堆
  - 装配五要素：知识 / 规则 / 专家能力 / 系统动作 / 权限凭证
  - 复杂业务拆成 Job 组合，每个 Job 独立挂权限与知识库
- **框架/术语**：三段式引导创建、业务上下文细颗粒拆分、能力五要素、Job 组合编排、技术骨架 Task 配置、`context_policy_code` 发布硬约束
- **项目对应**：[01-Methods/SOW-Spec-Demo证据链.md](../01-Methods/SOW-Spec-Demo证据链.md)、[03-Templates/需求说明清单.md](../03-Templates/需求说明清单.md)、[05-Engineering/Skill与Harness.md](../05-Engineering/Skill与Harness.md)、[05-Engineering/Production-Agent参考架构.md](../05-Engineering/Production-Agent参考架构.md)
- **Gap**：🔧补强——SOW 偏商业/Spec 视角，缺面向 Agent 上下文的三段式与"知识按结构拆颗粒"指引；Job 编排有 Skill/Harness 分工但无 Job 级模式；最大可吸收点是 `context_policy_code` 发布硬约束（项目有原则、缺可勾选工程门）
- **吸收建议**：Skill 与 Harness 或 Production-Agent 参考架构补"上下文策略绑定发布门"（非自动 Task 上线前必须绑定 context_policy）；SOW 或需求清单补"业务上下文按结构拆颗粒"指引（审批规则/FAQ/校验规则/风险判断/字段说明/错误案例六类）

### 稳定运行与运行态治理（页 14-17）

- **要点**：
  - 稳定运行是 Demo 进真实生产的分水岭
  - 运行时五能力：有状态调度、循环检测、断点续跑、状态快照、异常恢复
  - 观测—干预—恢复三位一体的运行态治理闭环
  - 产物包可追溯 + 版本一致性校验保证结果可复现可审计
- **框架/术语**：稳定运行分水岭、运行时五能力、Job 运行队列治理、可追溯产物包（诊断包/业务输出/trace/运行报告）、版本一致性校验、安全审计权限三件套
- **项目对应**：[01-Methods/生产化与采用.md](../01-Methods/生产化与采用.md)、[02-Playbooks/从原型到生产.md](../02-Playbooks/从原型到生产.md)、[05-Engineering/Production-Agent参考架构.md](../05-Engineering/Production-Agent参考架构.md)
- **Gap**：🔧补强——原则、生产最小包、分阶段上线、断点续跑/回滚/Runbook 均较完整覆盖；两处可补：版本一致性校验（本次环境版本与镜像比对）、Job 运行队列治理界面（后者属平台特性，方法层低优先级）
- **吸收建议**：在"从原型到生产"的重构门清单补一条"版本一致性校验：运行环境版本与当前镜像比对，保证可复现"；运行队列治理界面不强行复刻

### 业务价值可视化与人工审核（页 18-21）

- **要点**：
  - 企业不敢放行五件事：权限 / 责任 / 审计 / 异常处理 / 价值验收
  - 价值三视角：业务看任务跑没跑、IT 看系统稳不稳、管理层看投入产出
  - 业务看板五件套：运行量 / 处理效率 / 人工介入率 / 异常率 / 完成率
  - 统计口径必须声明纳入与排除边界及原因，否则数据不可信
  - HITL 审核点是价值验收的最小单元，把判断绑定到人责任上
- **框架/术语**：不敢放行五件事、治理能力组合、价值三视角、业务看板五件套、统计口径边界声明、HITL 审核点（原始件 + 结构化字段并排呈现）
- **项目对应**：[01-Methods/Eval与验收.md](../01-Methods/Eval与验收.md)、[01-Methods/生产化与采用.md](../01-Methods/生产化与采用.md)、[05-Engineering](../05-Engineering/)（HITL 责任接管 override）
- **Gap**：⚠️缺口——HITL 原则与责任边界已充分覆盖；缺 Agent 运行态看板五件套（项目采用指标偏用户行为：激活率/接管率/撤场留存）；更关键的是"口径必须声明边界"纪律未落到 Eval 每个指标的具体清单；"不敢放行五件事"散落在技术红线里未收口命名
- **吸收建议**：Eval 与验收或生产化与采用补"运行态业务看板"小节，五件套指标每项强制附口径声明（纳入范围/排除项及原因/按业务维度拆分）；把"不敢放行五件事"收口进企业 AI 技术红线作前置诊断清单，与现有四条红线互补

### 沉淀复用与平台收口（页 22-30）

- **要点**：
  - 复用=能力复利，否则退化外包、边际成本永远降不下来
  - 资源中心聚合可一键导出的注册能力包，含命令/YAML/校验/边界，不含密钥数据
  - 技能库管 Skill 的建传编绑删，复用度可量化
  - 工具库四维元数据（类型/风险/密钥/状态）+ 高风险分级复核；工具（原子）与 Skill（编排）解耦
  - 知识五步生产线：接通→建库→上传→检索评测→绑定；传上去不等于可用，必须测过
  - 首场景七要素选型，选对第一个比铺开做更重要
- **框架/术语**：任务资产八类、资源中心可导出能力包、技能库（复用度量化）、工具库四维元数据 + 风险分级、工具与 Skill 解耦、知识库五步生产线、平台五大体系、任务资产三层价值（业务/IT/组织）、四竞品对比、首场景七要素
- **项目对应**：[01-Methods/复用飞轮.md](../01-Methods/复用飞轮.md)、[05-Engineering/Skill与Harness.md](../05-Engineering/Skill与Harness.md)、[skills/](../skills/)、[01-Methods/Eval与验收.md](../01-Methods/Eval与验收.md)、[00-Map/FDE交付闭环.md](../00-Map/FDE交付闭环.md)
- **Gap**：🔧补强——复用飞轮 meta 层更成熟（三级资产 + 三硬指标 + 撤场复盘六问），首场景七要素基本被十维评分覆盖；四处可补：工具风险分级管控、Skill 复用度量化、任务资产三层 stakeholder 价值视角、知识五步生产线命名与量化口径
- **吸收建议**：Skill 与 Harness 补"工具风险分级"（低/中/高，高风险需人工复核 + 密钥单独引用）和"Skill 复用度指标"（被多少 Task 绑定）；复用飞轮补 stakeholder 价值映射表（业务看结果/IT 看治理/组织看复利）；知识五步生产线吸收进 fde-knowledge-ingest 的 references

## 本课最值得吸收的点

1. **补"7 大任务类型分类法"作机会诊断第二维度**：项目只用十维评分判"值不值得做"，缺"按类型分类判该怎么生产化、典型路径与风险"。可新增 01-Methods 文件，并作 fde-opportunity-diagnosis 在 Go/Hold/No-Go 之外的第二判断维度。
2. **补"业务运行态看板五件套 + 口径边界声明"**：采用指标偏用户行为，缺运行态指标（运行量/处理效率/人工介入率/异常率/完成率）。更关键的是把 README 已有的"数字必须说明样本口径"总原则，落到 Eval 每个指标的纳入/排除清单上。
3. **补"准确率八层面诊断清单"**：项目错误分类（数据/检索/规则/模型/工具/权限/流程）偏事后归类；课程提供更前置的八层面诊断（上下文/知识/Skill 设计/工具选择/执行/状态一致性/长链路可靠性/Runtime），可按层面逐项定位。
4. **补"`context_policy_code` 发布硬约束"**：项目有 Context 要素和"不可观测不可回放不可回滚不进关键流程"原则，缺一个可勾选工程门——非人工 Task 上线前必须绑定已注册上下文策略。落进从原型到生产的重构门清单。
5. **补"任务资产三层 stakeholder 价值映射"**：项目"三种最终资产"偏产物维度，缺按沟通对象切换的视角（业务看结果省时降异常、IT 看治理统一承接、组织看复利沉淀可复制能力）。在复用飞轮旁补一张映射表，对外汇报与作品集叙述可按对象说不同的话。
