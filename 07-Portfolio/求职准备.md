# FDE 求职准备

把交付案例变成 offer 的三件套：识别真岗位、简历四信号、面试考判断。受课程启发，用项目自己的话重述；详见 [来源登记](../06-Sources/来源登记.md)。

## 真假 FDE 岗位：五道压力测试

国内 title 不统一（FDE/解决方案架构师/交付工程师/AI 应用工程师），判断不看名看职责：是否进客户现场 + 是否对落地结果负责。五道全过才是真 FDE：

| 测试 | 真 FDE | 伪岗位信号 |
|---|---|---|
| 薪资结构 | 含销售提成/结果分成 | 纯固定工资，与结果无关 |
| 写代码占比 | 一半以上 | 主要做协调/PPT/汇报 |
| 产品反哺 | 有一线→产品反馈通道 | 只交付，不回流 |
| 进场时机 | 签单前进场参与定界 | 签单后才进场接需求 |
| 需求纠偏 | 有需求纠偏权限 | 只能照单执行 |

基准样本见 [FDE 资源矩阵](../08-Resources/FDE资源矩阵.md) 的 OpenAI FDE 岗位页。

## 简历四信号

招聘方扫简历找四个信号，项目经历要逐条对上：

| 信号 | 含义 | 怎么写 |
|---|---|---|
| Ownership | 端到端负责 | 用「我」不用「我们」，从需求到上线 |
| Customer Exposure | 客户接触面 | 写清客户上下文、现场工作 |
| Production | 生产环境真上了 | 区分 Demo 和生产 |
| Measurable Outcomes | 可量化结果 | 测试集/效率/边界三类数字 |

项目描述公式：动词 + 你构建的东西 + 客户上下文 + 量化结果。

没有商业数字也能量化三类：测试集指标（通过率/覆盖场景数）、效率指标（人天对比）、边界指标（异常场景数/人工介入点）。

项目经历五段式：业务背景 → 需求边界 → 方案选型 → 可验收结果 → 沉淀的可复用资产。把项目经历放在工作经历前面。

## 面试考判断

FDE 面试考「面对从没见过的问题你怎么思考」，不是算法和数据结构。备考头号错误是拿刷题路子准备。

- **拆解面（Decomposition）**：给模糊真实题（如「8000 条出租车记录一周内部署」），第一步是提问不是画架构。
- **Re-engineering 轮**：陌生代码 + 错误输出，看你怎么假设验证缩小范围。
- **Learning 轮**：现场给没见过的文档/DSL，看你怎么建心智模型。
- **Evals Engineering**：自设回归集、搭 LLM-as-Judge（OpenAI 挂人最多处）。
- **行为面**：备 3-5 个故事（ownership/艰难取舍/失败复盘/说服他人）按 STAR 压到两分钟。

四项日常练习（靠肌肉记忆，没法突击）：口述 Scoping、打开陌生 repo 先猜后验、读新工具文档 10 分钟讲心智模型、维护故事库。

项目的 [SOW-Spec-Demo](../01-Methods/SOW-Spec-Demo证据链.md) 可重写成拆解面起手式，[Eval 与验收](../01-Methods/Eval与验收.md) 可重写成 Evals Engineering 弹药。
